## 1. 요구사항 접수

### 1-1. 현상 기록

현상을 계층으로 나눠 적는다. **모델(가장 원초적) → 판정 → 실기 운영** 순이다.
아래층의 현상이 위층 설계를 결정했으므로, 위층만 보면 '왜 이렇게 만들었는지'가
설명되지 않는다.

#### (1) 모델 계층 — 데이터와 물리가 강제한 현상

| 번호 | 현상 | 설계에 준 귀결 |
|---|---|---|
| M-01 | **불량(NG) 표본이 극소수다.** 정상 수백 장당 불량 수십 장 수준이고, 불량의 양상도 제각각이라 같은 불량이 반복되지 않는다 | 불량을 '배우는' 분류 모델은 성립하지 않는다 → **정상만 학습**하고, 정상에서 벗어난 정도(복원오차)를 재는 방식을 채택 |
| M-02 | 점수 하나만 주는 모델은 현장에서 쓰이지 않는다. "이 웨이퍼 3.4점" 으로는 조치로 이어지지 않고, **어느 센서가 어느 구간에서** 벗어났는지가 있어야 한다 | 시점×센서 단위 오차가 나오는 구조 채택 — **과거 센서 + IO → 미래 센서 예측** 후 실제와 대조. 점수와 함께 원인 센서·문제 구간이 부산물로 나온다 |
| M-03 | **IO(밸브 개폐)가 센서 거동의 원인이다.** 밸브가 열리면 유량·압력이 급변하는데 이것은 정상이다. 센서만 보는 모델은 이 정상적 급변을 이상으로 오인한다 | IO 를 모델 입력에 포함 — 밸브 조작이 예고된 급변은 예측에 반영되어 오차가 커지지 않는다. 인과(원인=IO → 결과=센서) 방향을 모델 구조에 심음 |
| M-04 | **공정 첫 스텝은 정상인데도 오차가 크다.** 이전 공정의 잔류(carryover) 상태가 웨이퍼마다 달라, 시작 직후 센서값이 흩어진다 | 판정에서 첫/끝 스텝 제외 + 스텝별 표준화. '어디부터 판정 구간인지'를 명시하고 화면 음영도 이를 따른다 |
| M-05 | **유형(레시피)마다 점수의 크기가 다르다.** 전역 임계 하나로 자르면 어떤 유형은 전부 불량, 어떤 유형은 전부 양품이 된다 | 유형별 임계(`search_best.json`)를 학습 산출물로 채택 + 현장 조정용 유형별 배율. 점수를 임계=1 로 정규화해 유형이 섞여도 한 축에서 비교 |
| M-06 | **공정 길이가 웨이퍼마다 다르다.** 오차를 시간축으로 누적하므로 긴 공정일수록 점수가 커진다 | 타임포인트 정규화 모드(점수÷유효 스텝 수). 단 모델이 이미 평균화 방식으로 학습된 경우(score-avg 계열) 앱이 또 나누면 이중 정규화 — 자동 감지해 무시 |
| M-07 | **학습 프레임워크(torch) 최신판이 윈도우7 에서 로드조차 안 된다.** torch 2.4.1 의 DLL 이 Windows 8 전용 API(CreateFile2)를 정적 임포트한다(임포트 테이블 실측) | 학습과 추론을 분리 — 추론은 onnx 로. onnxruntime 도 1.15.1 부터 같은 문제라 **1.14.1 상한**, 학습앱이 내는 IR 10 모델을 위해 IR 하향 도구를 배포에 포함 |
| M-08 | **임계 없이 점수만으로는 판정할 수 없다.** 모델 폴더에 임계 파일이 빠진 채 배포되는 경우가 실제로 있었다 | 임계 부재 시 0 이나 임의값을 만들지 않고 **판정 보류**로 명시. 등급 집계에서도 보류를 별도 표기 |
| M-09 | 밸브 조건별 가중(배점) 점수 S(w) 는 원점수와 분포가 달라, **모델이 준 임계(원점수의 3σ)를 그대로 쓰면 판정이 왜곡된다** | 배점 모드 전용 임계 θ(w) 재보정 절차(OK 재추론 또는 분위수 매칭 — 오탐률을 보존한 채 이관) |

#### (2) 판정·집계 계층 — 운영하며 드러난 현상

| 번호 | 현상 | 설계에 준 귀결 |
|---|---|---|
| J-01 | 임계는 '한 장이 넘었는가'만 본다. **아무도 안 넘었지만 서서히 나빠지는 흐름**은 잡히지 않는다 | 묶음 단위 산포 지표(초과 강도) 도입 — 후속으로 묶음 기준이 문제가 됨(F-01) |
| J-02 | 등급 경계(경고·심각 배수)를 감으로 정하면 근거를 대지 못한다 | OK 분포의 로그공간 σ 로 자동 산출(경고=exp(σ)·심각=exp(2σ) — 임계가 μ+3σ 이므로 정확히 4σ·5σ 지점) |
| J-03 | 같은 웨이퍼를 재검사하면 집계가 이중으로 센다 | 일·기간 집계는 웨이퍼당 최근 결과 1건만 사용 |
| J-04 | 판정 기준을 바꾸면 과거 이력과 어긋난다 | 이력에 원점수를 보존하고 **표시만 재계산** — 기준 변경이 소급 적용되되 원본은 불변 |

#### (3) 실기 운영 계층 — 윈도우7 제어기 적용에서 관측된 현상

개발 환경(윈도우11 + 인터넷)에서는 전부 정상으로 보였고, 실기에서만 드러났다.

| 번호 | 현상 | 관측 상황 | 영향 |
|---|---|---|---|
| F-01 | 산포 추세가 실제 품질과 어긋남 | 설비가 쉬거나 몰아 돌린 구간 | 한 LOT 이 쪼개지거나 두 LOT 이 붙어 값이 뭉개짐 |
| F-02 | 조회기간의 **시간을 입력할 수 없음** | 제어기 브라우저(Firefox) | 사용자 지정 조회가 **전면 불가**. 원래 화면(달력+시간 목록)은 앱 UI 가 아니라 크롬의 datetime-local 렌더링이었음 |
| F-03 | 화면 글씨체가 개발 PC 와 다름 | 제어기(인터넷 없음) | 외부 CDN 글꼴을 못 받아 폴백 — 모양이 달라 보이고 첫 화면 지연 |
| F-04 | 폴더 선택 창이 앱 뒤에 뜸 | [찾기] 클릭 시 | OS 대화상자는 셸이 만드는 창이라 '항상 위'를 물려받지 않고, 윈7 포그라운드 잠금으로 끌어올릴 수도 없음 |
| F-05 | LOT 채우기 중 저장 파일이 생기지 않음 | 11만 장 처리 중 | 첫 저장이 늦고, **저장 실패가 except: pass 로 삼켜져** 완료로 오인될 구조 |
| F-06 | 경로 저장이 수십 초 걸림 | 대용량 폴더 등록 | 저장 응답이 폴더 전체를 훑어 개수를 세고 있었음 |
| F-07 | LOT 채우기가 20분 넘게 진행 | 11만 장 | 진행률·예상 시간이 없어 멈춤과 구분 불가 |
| F-08 | 다른 탭으로 이동하면 진행률이 사라짐 | LOT 채우기 중 | 서버 작업은 계속되나 화면이 몰라 취소로 오인 |
| F-09 | 화면의 숫자가 어떻게 나온 값인지 알 수 없음 | 전 화면 | 근거를 못 대면 신뢰가 서지 않음 |
| F-10 | LOT 값이 실제와 다름 | 전 데이터 | **G2 로 알고 구현했으나 실제는 I2.** 셀만 고치면 기존 기록이 전부 건너뛰어져 틀린 값이 잔존하는 구조적 문제 동반 |
| F-11 | 콘솔 창이 항상 함께 뜸 | 앱 실행 시 | 현장 사용에 거슬림. 단 콘솔 제거는 진단 수단 대체가 선행돼야 함 |

## 2. 요구사항 개발

### 2-1. 변경 범위 입력

**모델 전제 — 변경하지 않지만 이번 개정 전체를 구속하는 것**

모델 계층(M-01~09)은 이번 개정에서 **건드리지 않는다.** 그러나 그 현상들이 이번
개정의 설계를 아래와 같이 구속한다. 이 매핑이 없으면 "왜 이렇게밖에 못 만들었는지"가
설명되지 않는다.

| 모델 전제 | 이번 개정에 준 구속 |
|---|---|
| M-01 정상 학습·복원오차 방식 | 점수는 '정상 대비 벗어난 정도'다. LOT 산포(초과 강도)도 양·불 판정이 아니라 **벗어난 정도의 묶음 통계**로 설계한다 |
| M-02 시점×센서 오차 구조 | 계산 설명(?)의 센서·누적 항목은 이 구조를 그대로 서술해야 한다 — 0~1/1~2 눈금 차이, 음영=기울기 기준 |
| M-05 유형별 임계·임계=1 정규화 | 초과 강도의 기준선 1 은 이 정규화가 전제다. **유형이 섞인 LOT 도 한 축에서 묶을 수 있는 근거**이며, LOT 산포 설계는 이 위에서만 성립한다 |
| M-06 타임포인트 정규화(이중 정규화 금지) | 표시 규칙·설명 문구가 모델의 score_norm 을 확인해 자동 분기해야 한다 — 설명(?)에도 이 예외를 명시 |
| M-07 onnx 분리·onnxruntime 1.14 상한 | 이번 개정의 모든 코드가 **파이썬 3.8 / FF115 세대**에서 돌아야 한다. IR 하향 도구는 배포물에 유지 |
| M-08 임계 부재 = 판정 보류 | 신규 화면(1시간 현황·달력·산포)도 보류를 0 이나 양품으로 흡수하면 안 된다 |
| M-09 배점 점수 θ(w) 재보정 | 배점 모드 설명(?)은 '왜 모델 임계를 그대로 못 쓰는지'를 포함해야 한다 |

**변경 대상**

| 구성요소 | 파일 | 변경 성격 |
|---|---|---|
| 산포 계산 | `server.py` — `_dispersion_groups` | 그룹 기준 교체 |
| 로그 태깅 | `server.py` — `_extract_lot_from_log` 외 | 항목 추가 |
| LOT 보강 | `server.py` — `/api/lot-*` | 신규 |
| 화면 | `static/index.html` | 옵션 정리 · 설명 추가 · 입력 방식 교체 |
| 내보내기 | `export_html.py` | 자원 내장 |
| 실행 진입 | `launcher.py` · `desktop.py` | 알림창 속성 |
| 빌드 | `io_console_win7.spec` | 콘솔 옵션화 |
| 문서 | `win7_pkg/*` · `docs/*` | 안내 갱신 · TC |

**변경하지 않는 것 (경계)**

| 대상 | 이유 |
|---|---|
| 모델 추론 로직 | 판정 결과가 달라지면 안 된다 (M-01~04 의 산출 구조 그대로) |
| 모델 산출물 계약 | `.onnx` + `recon_meta.npz` + `search_best.json` 의 형식·의미 불변 — 학습 앱과의 경계(M-05·M-07) |
| 임계·정규화 계산식 | 임계=1 정규화, per_tp 분기, θ(w) 절차 모두 기존 그대로 (M-05·M-06·M-09) |
| 저장된 이력의 원점수 | 표시 규칙만 바꾸고 원본은 보존 (J-04) |
| 학습 앱 | 별도 시스템 |
| 검사 파이프라인의 순서 | 이번 요청과 무관 |

### 2-2. 제약 사항 정의

| 번호 | 제약 | 설계에 준 영향 |
|---|---|---|
| D-01 | 기존 이력을 버릴 수 없다 | LOT 은 재검사 없이 원본 로그에서 보강 |
| D-02 | 판정 결과가 바뀌면 안 된다 | LOT 보강은 파일당 두 줄만 읽고 점수는 건드리지 않음 |
| D-03 | 로그 열 위치가 또 바뀔 수 있다 | 칸 위치를 화면 설정으로 노출 |
| D-04 | 칸이 바뀌면 기존 값은 틀린 값이 된다 | **읽은 칸을 함께 기록**해 불일치 시 자동 재추출 |
| D-05 | 인터넷 없음 | 외부 자원 전면 금지 — 글꼴 내장 |
| D-06 | 구버전 브라우저 | 그 버전 이후 기능 사용 금지 |
| D-07 | 네트워크 드라이브 접근이 느리다 | 병렬 읽기 · 진행률 · 중간 저장 |
| D-08 | 콘솔을 없애면 오류를 볼 수단이 사라진다 | 파일 로그 · 오류 파일 · 알림창을 선행 확보 |
| D-09 | 대용량 처리 중 중단될 수 있다 | 주기 저장 — 중단돼도 남은 것만 이어서 |
| D-10 | 설명은 구현과 어긋나면 안 된다 | 설명 근거를 코드 주석으로 상호 참조 |

**모델 계층에서 내려온 제약** (이번 개정이 지켜야 하는 모델 쪽 사실)

| 번호 | 제약 (출처) | 설계에 준 영향 |

### 3-2. LOT 추출과 재추출 규칙

**변경 전** — 해당 기능 없음. 산포는 시간 간격만 사용.

**변경 후**

```
태깅 시점(검사 중 또는 LOT 채우기)에 파일당 다음을 기록한다.

    file_meta.json
      "WUK370A_w0001": {
          "chamber": "dsv5",        ← C2
          "lot"    : "7c218394…",   ← I2   ★신규
          "lot_c"  : "R2C9",        ← 어느 칸으로 읽었는지  ★신규·핵심
          "lot_v"  : 1,             ← 읽어는 봤다(값이 비어도 세움)
          "end_ts" : "2026-08-01T09:02:00"
      }

건너뛰기 판정:
    lot_c == 현재 설정된 칸  →  건너뜀
    lot_c != 현재 설정된 칸  →  다시 읽고 덮어씀   ★칸을 바꾸면 자동 재추출
    force(처음부터 다시 읽기) →  무조건 다시 읽음
```

**`lot_c` 가 필요한 이유** — 기본값만 G2→I2 로 바꿨다면 아무 일도 일어나지 않는다.
이미 읽은 파일은 전부 건너뛰어 **틀린 값이 그대로 남는다**. 읽은 칸을 함께 기록해야
설정 변경이 재추출로 이어진다.

**검증** — I열에 진짜 LOT, G열에 다른 값을 넣은 파일

| 단계 | 결과 |
|---|---|
| I2 로 읽기 | 6장 정상 추출 |
| 같은 칸 재실행 | 0장 (건너뜀) |
| G2 로 변경 | 6장 재추출 → G열 값으로 덮임 |
| I2 로 복귀 | 6장 재추출 → 원래 값 복구 |
| 값 없는 칸으로 변경 | 6장 읽고 채움 0 · **옛 값도 삭제** |
