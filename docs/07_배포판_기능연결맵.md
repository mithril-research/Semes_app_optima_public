# 배포판 기능 연결 맵 — 버튼 → API → 저장소

작성 2026-09-04 · 배포판 재구성(C안) 반영. **기능을 넣거나 뺄 때 이 맵을 갱신하고,
여기 적힌 연결을 전부 따라가며 확인한다** — metadata↔history 사고 재발 방지 문서.

## 1. 영속 상태 — 배포판에서 남은 것 (11곳 → 5곳)

| 저장소 | 위치 | 역할 | 지워지는 때 |
|---|---|---|---|
| **아카이브(웨이퍼 npz)** | 보관\<날짜>\ | **유일한 검사 결과 원본** — 이력·산점도·추이·달력·상세 전부 여기서 | 1~60일 자동 정리, 0000=무제한 / [검사 이력 전체 삭제] |
| app_config.json | **앱 폴더**(데이터와 분리) | 폴더 등록·기본 모델·표시 규칙 등 설정 | 사용자가 직접 |
| autopilot.json | 데이터\ | 마감 날짜 + 자동검사 토글 **(처리목록 저장 안 함)** | - |
| file_meta / recipe_tags / n_tp | 데이터\ | 파일 속성 태그(끝시각·챔버·LOT·레시피·타임포인트 수) | [전체 삭제] |
| custom_models.json | 데이터\ | 직접 입력한 모델 폴더 목록 | 사용자가 직접 |

**제거된 것**: history.jsonl(이력 파일) · score_cache · parse_cache · 집계 TTL 캐시 ·
metadata.csv(파일 생성 자체) · storage.json · recipe_multipliers.json · GPU/배치 설정 ·
LOT 채우기 경로 · overlay 민감도 설정(0.8 고정).
유지된 메모리 캐시: 재판정(_RELIVE)·산점도(_SCATTER) — 서명 기반·파일 없음·stale 불가.

UI 갱신: HTML(`/`, `/static/index.html`)과 `/api/*` 응답은 `Cache-Control: no-store`.
브라우저 런처와 WebView2는 화면을 열 때마다 고유 URL을 사용해 기존 HTML 캐시도 우회한다.
`/api/ping-app`의 시작 시점 코드 해시·설치 위치가 모두 같을 때만 기존 서버를 재사용한다.
구버전(식별 정보 없음 포함)이나 다른 설치의 서버가 남아 있으면 옛 UI에 연결하지 않는다.
즉시 시작 실패로 처리하지 않고 최대 330초(구버전의 첫 화면 대기 300초 포함) 동안 포트 해제를
기다린 뒤 새 서버를 시작한다. 작업 중인 기존 프로세스는 강제 종료하지 않는다.
짧게 열고 닫은 화면도 연결 이력을 즉시 기록해 첫 화면 대기 300초가 잘못 적용되지 않게 한다.
화면의 API 요청에도 `cache: no-store`를 적용한다. 응답의 서버 인스턴스가 바뀌거나
Firefox 뒤로가기 캐시(`pageshow.persisted`)에서 복원되면 고유 URL로 문서를 다시 읽는다.
검증: `python -m unittest discover -s tests -p test_ui_runtime.py`.
실제 브라우저 검증: `python tests/check_firefox_ui_cache.py --firefox <Firefox 실행파일 경로>`.
Firefox 115.0 ESR 한국어 Linux x64에서 API 캐시 우회·서버 교체 재로딩·실제 bfcache 복원 통과.

## 2. 단일 소스 흐름

```
검사(수동/자동) → _archive_wafer(npz: meta_json에 이력 전체 필드+lot)  ← 영속(유일)
              → _append_history(메모리 인덱스 갱신)                    ← 파생(비영속)
시작/재시작   → _hist_index_ensure(): 보관\ 전체 1회 스캔 → 인덱스 재구축
화면(산점도·추이·달력·1시간·산포) → _read_history() = 인덱스 조회
자동검사 처리 판정 → _is_processed(stem) = 인덱스에 현재 모델로 있음?
```

## 3. 핵심 버튼 연결

| 버튼/동작 | API | 만지는 상태 | 결과 보장 |
|---|---|---|---|
| 검사 이력 전체 삭제 | POST /api/archive/clear | 보관\ 삭제 + 인덱스 리셋 + _reset_recognition_state(태그·구캐시 폴더·화면상태) + 구 history*.jsonl 잔재 삭제 | 다음 자동검사 주기(5초)에 **전체 재검사 자동 시작** |
| 자동검사 토글 | POST /api/autopilot/toggle | autopilot.json(enabled) | 꺼짐=신규검사만 정지(마감·보관정리는 계속), 켜면 밀린 파일 소급 |
| 모델 전환 | POST /api/model/select | ENGINE + 화면상태 초기화 | 인덱스가 모델별이라 **자동으로 전체 재검사**(별도 리셋 불필요) |
| 보관 기간 저장 | POST /api/archive-retention | 입력 0→60일, 0000→unlimited=true→설정값 0(무제한), 1~60→해당 일수 | 무제한 설정이면 아카이브·이력 인덱스·메타데이터·백업·로그 자동 삭제 안 함. 기간 보관이면 저장 즉시 아카이브 정리, 정기 정리에도 같은 기간 적용 |
| 자동검사 표시 | GET /api/autopilot (2.5초 폴링) | - | last_scan 변경 시 진행바 깜빡 + '마지막 자동검사 시각' 상시 |

## 챔버별 모델 묶음 (2026-09-08)

설정 → 검사 모델에서 DSV별 모델이 담긴 **상위 폴더**를 선택하고 적용한다.
현재 로드된 DSV별 ONNX 경로를 설정 화면에 표시한다.

```text
선택폴더/
  DSV1/
    tcn_forecast.onnx
    recon_meta.npz
    search_best.json
    best_search.json       # 선택: search_best.json 없으면 이 파일 사용
  DSV2/ ...
  ...
  DSV6/ ...
```

- ONNX 파일명은 `tcn_forecast` 철자에 고정하지 않는다. 챔버당 ONNX는 하나만 둔다.
- DSV1~DSV6 하위 폴더 이름은 대소문자를 구분하지 않는다.
- 각 하위 폴더의 `recon_meta.npz` 또는 ONNX와 같은 이름의 NPZ를 사용한다.
  설정은 `search_best.json`을 우선하고, 없으면 `best_search.json`을 사용한다.
- 한 폴더에 DSV 접두사 파일을 나열하는 방식은 지원하지 않는다.
- `.log/.tsv`의 **실제 2행 C열(C2)**: PMCUNIT7→DSV1, 8→DSV2, 9→DSV3,
  10→DSV4, 11→DSV5, 12→DSV6. 예전 C3 태그는 원본을 다시 읽어 C2 기준으로 갱신한다.
- 챔버별 모드에서 C2를 확인할 수 없거나 해당 챔버 모델이 없으면 오류로 처리한다.
  파일명·폴더 이름으로 다른 챔버 모델을 대신 적용하지 않는다.
- 수동·자동 검사 모두 챔버별 설정으로 데이터를 정렬하고, 동일 챔버의 여러 웨이퍼를
  `predict_batch`로 추론한다. 기본 파일 청크는 200매(`IO_INSPECT_CHUNK`), ONNX 내부
  윈도우 배치는 기존 메모리 제한을 따른다. 자동검사도 청크 단위로 원본 배열을 해제한다.
- 개별 판정·아카이브·상세 그래프는 해당 챔버 엔진을 사용한다. 요청별 엔진 선택은
  ContextVar로 격리한다. 모델 선택은 전체 로드에 성공했을 때 교체하며 실패 시 기존 모델을 유지한다.
- 이력 모델 ID는 C2 챔버 판독 규칙과 모든 챔버의 ONNX·NPZ·JSON 내용 해시다.
  C3 기준 검사 결과는 재사용하지 않으며, 원본이 있으면 자동검사에서 다시 검사한다. 폴더 이동만으로 변하지 않으며
  챔버 모델을 변경하면 이전 묶음 이력과 분리된다. 재시작 시 NPZ의 챔버 정보로 임계를 적용한다.
- 기존 단일 모델 폴더도 계속 사용 가능하다. 모든 챔버에 같은 모델을 적용한다.

연결: `/api/model/select` → `Engine`/`chamber_models.py` → 챔버별 `_load_aligned` →
`_prefill_batch` → `_result_for` → `_archive_wafer` → 현재 모델 이력 및 상세 API.
RCA 디렉터리 로더에는 해당 챔버 파일만 들어 있는 임시 폴더를 전달한다.

검증: `python -m unittest discover -s tests -p test_chamber_models.py`
(FastAPI, onnx, onnxruntime, NumPy 및 앱 의존성 필요).
생성한 ONNX 모델로 배치/개별 결과 일치, 챔버별 임계, 수동·자동 로그 검사,
아카이브 재조회, 설정 API를 검증한다. 실제 고객 모델 성능 및 Windows EXE 실행은 별도 확인 대상이다.
