# 배포 환경 시뮬레이션 시나리오 — 항상성 검증

작성 2026-09-04 · 실행 하네스: `app/sim_deploy.py` (실제 server.py 코드로 구동)

## 전제 (배포 환경 모사)

- 챔버 폴더에 웨이퍼 .csv 가 **순차 유입**된다(설비가 쓰는 것과 동일).
- **자정 롤오버**: 날짜가 바뀌면 마감·보관 정리가 돈다. 보관 60일 상한.
- 공정 엔지니어는 **아무 때나** 이력을 지우고, 설정을 바꾸고, 모델을 바꾼다.
- 그 동안에도 데이터는 계속 들어온다.

## 불변식 (매 단계 후 전부 검사 — 하나라도 깨지면 실패)

| # | 불변식 |
|---|---|
| I1 | 어떤 API 도 예외/500 을 내지 않는다 (overview·scatter·sensors-all·dispersion) |
| I2 | 유입된 모든 안정 파일은 결국 검사된다 (자동검사 누락 0) |
| I3 | 같은 파일이 같은 모델로 두 번 검사되지 않는다 (중복 0) |
| I4 | 웨이퍼 점수·판정은 항상 유한값 (NaN/None/음수 없음) |
| I5 | **개별 센서 점수 조회(sensors-all)가 절대 에러 나지 않고, 값이 유한** |
| I6 | 이력 인덱스 = 아카이브 폴더 내용 (행 수 일치) |
| I7 | 전체 삭제 후 다음 스캔에서 전량 재검사가 시작된다 |
| I8 | 모델 교체 후 다음 스캔에서 전량 재검사가 시작된다 |
| I9 | 재시작(인덱스 재구축) 후 이력 행 수·점수가 이전과 동일 |
| I10 | 손상 아카이브 파일이 있어도 앱이 죽지 않고 그 파일만 제외된다 |

## 시나리오

S1  기본 흐름 — 빈 상태 → 3장 유입 → 스캔 → 이력 3·중복 0·센서점수 정상
S2  순차 유입 — 2장씩 3회 유입, 매회 스캔 → 신규만 검사(중복 0)
S3  자정 롤오버 — 날짜 +1 → 마감·정리 → 다음날 유입 검사 정상
S4  이력 전체 삭제 → 즉시 다음 스캔에서 전량 재검사 + 삭제 직후 유입분 포함
S5  모델 교체 → 전량 재검사, 새 모델 점수로 이력 갱신(같은 웨이퍼 1행 유지)
S6  설정 변경 조합 — 보관기간 60→30→60, 표시 모드 raw↔per_tp, 자동검사 on/off — 각 조합 후 I1~I6
S7  자동검사 off 중 유입 → on → 소급 검사
S8  난동 조합 — [삭제→교체→유입→삭제→off→유입→on→교체] 연타 후 전 불변식
S9  재시작 — 인덱스 리셋 후 재구축 → 행 수·점수 동일
S10 손상 주입 — 아카이브에 깨진 npz 추가 → 재구축 시 그 파일만 제외, API 정상

## 판정

- 모든 시나리오 × 모든 불변식 통과 = PASS.
- 실패 시 시나리오·불변식 번호와 상태 덤프를 출력한다.
