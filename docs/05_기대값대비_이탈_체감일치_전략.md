# 기대값 대비 이탈 — "눈에 보이는 것"과 "점수"를 일치시키는 전략

작성 2026-09-01 · 대상: 이상분석 탭의 센서별 이상점수·그래프
상태: **전략 수립 단계**(구현 전). 아래 측정치는 실제 모델·실제 웨이퍼로 확인한 값이다.

---

## 0. 문제 제기 (사용자)

> 기대값의 시그마 범위가 넓으면 육안으로 많이 차이가 나도 높은 점수를 못 받고,
> 시그마 범위가 작으면 육안으로 차이가 적어도 핵심 문제로 뽑힌다. 이용자가 헷갈려한다.

---

## 1. 현재 산식 — 눈과 점수 사이에 변환이 **세 단계** 있다

```
① 시점 정규화   level(t,j) = |실측 − 기대| ÷ resid_abs_limit[step, j]
                 resid_abs_limit = OK 웨이퍼 잔차의 99퍼센타일 (스텝별·센서별)

② 시간 적분     accum(j)   = Σ_t level(t,j)          ← 웨이퍼 전 구간 누적

③ 코호트 정규화 r(j)       = accum(j) ÷ ok_hi(j)     ← OK 웨이퍼들의 누적 상한
                 센서 막대 점수 = r (r≤1) 또는 1+(r−1)/(r_max−1) (r>1)
```

**화면의 센서 그래프는 ①의 입력(물리 단위)만 보여준다.** ②와 ③은 화면 어디에도
나타나지 않는다. 사용자는 ①의 입력을 보고 ③의 출력으로 매겨진 순위를 읽는다.

---

## 2. 측정 — 원인이 무엇인지 실제로 확인

### 2-1. 시그마(분모) 폭 편차 → **주원인이 아니다**

`artifacts/recon_meta.npz` 의 `resid_abs_limit` 을 센서 자체 물리 산포(`sen_std`)로 나눈 값
= 화면에서 정상범위 밴드가 차지하는 상대 폭.

| | 최소 | 중앙 | 최대 |
|---|---|---|---|
| 분모 ÷ 센서 물리 산포 | 0.71 | 1.60 | 2.73 |

가장 좁은 분모와 가장 넓은 분모의 비가 **4배**다. 센서 12개 모두 0.7~2.7 범위 안에
들어 있고, "시그마가 거의 0이라 조금만 벗어나도 폭발"하는 병적 센서는 이 모델에 없다.
→ 사용자가 지목한 기전은 **실재하지만 지배적이지 않다**. (다른 레시피·재학습 모델에서
커질 수 있으므로 방어책은 필요 — 5-3 참조)

### 2-2. 진짜 원인 = **적분(지속시간)** — 눈은 진폭을, 점수는 지속을 본다

실제 NG 웨이퍼(RLWAFER2, T=1500, 12센서) 측정.
※ `보관/` 에 npz 가 3개 있으나 **셋의 z 배열 해시가 동일** — 같은 웨이퍼가 세 이름으로
저장된 것이다. 따라서 아래는 **웨이퍼 1장 표본**이며, 일반화하려면 실데이터 추가 확보가
필요하다(기전 확인에는 충분하나 계수 결정에는 부족).

| 센서 | 눈에 보임(차트 높이 %) | 눈 순위 | 순간 최대 이탈 | 1배 초과 지속 | 누적 | 점수 순위 |
|---|---|---|---|---|---|---|
| t_001_PV | 88.9% | 1 | 12.20배 | 86% | 6008 | 1 |
| t_004_PV | 84.1% | 2 | 10.46배 | 71% | 4862 | 2 |
| **t_003_PV** | **48.9%** | **11** | **3.75배** | **83%** | **2974** | **5** |
| p_007_PV | 76.9% | 5 | 4.38배 | 66% | 2365 | 7 |
| p_006_PV | 56.0% | 9 | 3.18배 | 17% | 868 | 11 |

- 눈 순위 vs 점수 순위 상관 **+0.84** (3계단 이상 어긋남 1/12 센서)
- `t_003_PV` 이 정확히 사용자가 말한 사례다. 순간 최대는 3.75배로 12개 중
  하위권인데 **83% 구간에서 계속 벗어나** 누적이 커져 5위로 올라왔다.
  분모 폭은 1.38로 평범하다 — **시그마 탓이 아니라 지속시간 탓이다.**

### 2-3. 보조 원인 = 센서마다 y축이 제각각(autoscale)

각 센서 차트의 y축은 그 센서의 `min/max(실측, 기대, 밴드)`로 자동 설정된다.
따라서 **두 센서 차트의 벌어짐을 눈으로 비교하는 행위 자체가 성립하지 않는다.**
같은 "차트 높이의 50%"가 센서 A에서는 2배 이탈, 센서 B에서는 0.6배 이탈일 수 있다.

---

## 3. 전략 원칙

> **웨이퍼 OK/NG 판정 점수는 건드리지 않는다. 설명(그래프)과 센서 랭킹만 고친다.**

판정식을 바꾸면 임계 재보정·정답수 재검증·기존 이력과의 불연속이 따라온다.
사용자 불만은 "판정이 틀렸다"가 아니라 **"왜 이 센서가 1등인지 납득이 안 된다"**이므로
설명 계층에서 해결하는 것이 비용·위험 모두 낮다.

---

## 4. 전략 — 위험이 낮은 순서

### 단계 0 — 왜곡 없이 혼란만 제거 (무위험, 즉시)

**S1. 점수 근거 3종 병기.** 지금은 누적 하나만 막대로 나온다. 센서 막대 옆에 함께 표시:

```
t_003_PV   ████████░░  1.42
   순간 최대 3.8배 · 초과 지속 83% · 누적 2974
```

"순간은 작지만 오래 벗어나서 높다"가 한 줄로 읽힌다. 이것만으로 문의의 상당수가 사라진다.

**S2. 분자·분모·배수 병기.** 그래프 툴팁에 물리량과 배수를 같이:

```
최대 벌어짐 0.83 ℃  ÷  정상폭 0.22 ℃  =  3.8배
```

지금은 배수만 보이거나 물리량만 보인다. 분모가 안 보이는 것이 혼란의 직접 원인이다.

### 단계 1 — 화면을 점수 쪽에 맞춘다 (표시만 변경, 검출력 불변)

사용자가 "기대값을 왜곡하더라도"라고 한 부분이 여기에 해당한다. 두 안이 있다.

**S3. 이탈 배수 뷰 (토글).** y축을 `level`(배수)로 바꿔 그린다. 0=일치, 1=정상 경계.
모든 센서가 같은 축을 쓰므로 차트끼리 눈으로 비교가 성립한다.
- 장점: 눈과 점수가 정의상 일치. 구현 간단(데이터 이미 있음).
- 단점: 물리 단위 감각이 사라진다(몇 ℃ 벗어났는지 안 보임).

**S4. 밴드 폭 고정 뷰 (권장).** 물리 단위를 유지하되 **y축 범위를 `기대 ± k·정상폭`으로
고정**한다(k=4 정도). 정상범위 밴드가 어느 센서에서나 화면에서 같은 높이를 차지한다.
- 눈에 보이는 벌어짐 ∝ 이탈 배수 가 성립하면서 축 눈금은 여전히 ℃·Torr다.
- 밴드를 크게 벗어난 구간은 화면 밖으로 나가므로, 잘린 구간은 위/아래 화살표로 표시.
- **S3보다 이쪽을 권장** — 공정 엔지니어가 물리 단위를 잃지 않는다.

두 안 모두 기본 뷰(현재 방식)를 없애지 않고 토글로 추가한다.

### 단계 2 — 랭킹을 눈 쪽에 맞춘다 (센서 순위만, 판정 불변)

**S5. 진폭·지속 균형 랭킹.** 현재 랭킹은 순수 적분이라 지속시간이 진폭을 압도한다.
기하평균으로 두 축을 같은 비중으로:

```
rank_score(j) = √( 누적정규화(j) × 순간최대정규화(j) )
```

- 오래 벗어난 센서와 크게 튄 센서가 모두 상위에 남는다.
- 실측(웨이퍼 1장): 눈 순위 상관이 **0.839 → 0.874** 로 개선. 순간최대 단독은 0.895.
- **단, 이 수치로 '순간최대가 낫다'고 결론내면 안 된다.** 여기서 쓴 '눈에 보임' 지표는
  `max|실측−기대| ÷ y축 범위` 로 **그 자체가 진폭(peak) 측도**다. 진폭 기반 랭킹이
  진폭 기반 대리지표와 잘 맞는 것은 동어반복이다. 이 상관은 "적분과 진폭이 실제로
  다르다"는 기전 확인에만 쓸 수 있고, 둘 중 무엇이 옳은지는 판정하지 못한다.
- 무엇이 옳은지는 **공정 엔지니어의 판단**이 기준이어야 한다 → 6절 참조.
- 막대 점수(0~2 스케일)의 의미는 유지하고 정렬 기준만 바꾸는 안도 가능.

**S6. 분모 클리핑 (보험).** 2-1에서 현 모델은 문제없음을 확인했으나, 재학습·신규 레시피
에서 분모가 병적으로 좁아지는 것을 막는 안전장치:

```
denom = clip( resid_abs_limit,  κ·sen_std,  τ·sen_std )     κ=0.5, τ=3.0
```

`sen_std` 는 이미 `recon_meta.npz` 에 있으므로 **재학습 없이 기존 배포 모델에도 적용 가능**.
현 모델(0.71~2.73)은 이 범위 안이라 값이 하나도 안 바뀐다 — 순수 방어용.
현재 `raw_error_min = 1e-9` 는 0 나누기 방지일 뿐 하한 역할을 못 한다.

---

## 5. 하지 않을 것

- **판정 점수·임계 변경** — 3장 원칙. 필요해지면 별도 과제로.
- **기대값 곡선 자체를 실제로 바꾸는 것** — 모델 출력을 손대면 RCA·반사실 검증이
  전부 흔들린다. "왜곡"은 **표시 축**에서만 한다(S4).
- **적분 폐기** — 지속시간은 실제로 중요한 정보다. 진폭과 **병기**하고 균형만 맞춘다.

## 6. 검증 계획

| 항목 | 기준 |
|---|---|
| 웨이퍼 판정 정확도 | **변화 없어야 함**(S1~S5 는 판정에 미개입) — 필수 관문 |
| 앱 ↔ 내보낸 HTML | 같은 웨이퍼에서 막대 순서·값 완전 일치 |
| 센서 랭킹(S5) | 아래 '사람 기준' 절차로 판정 |

**S5 의 검증은 자동 지표로 할 수 없다.** 진폭 대리지표로 진폭 랭킹을 평가하면 반드시
진폭이 이긴다(동어반복). 대신 다음 절차를 쓴다.

1. NG 웨이퍼 10~20장을 뽑아, 각 웨이퍼의 센서 그래프만 보여주고 엔지니어가
   "가장 문제인 센서 3개"를 고르게 한다(점수는 가린다).
2. 그 선택을 정답으로 두고 현재 랭킹 / 기하평균 랭킹의 상위 3개 적중률을 비교한다.
3. 적중률이 같으면 **현재 방식을 유지**하고 단계 0·1(설명·표시)만 적용한다.

전제 조건: 현재 `보관/` 에는 서로 다른 웨이퍼가 1장뿐이므로, **실데이터 확보가 이 검증의
선행 과제**다. 확보 전까지는 단계 0·1 만 진행한다(판정·랭킹 미변경이라 안전).

## 7. 권고

```
단계 0 (S1·S2)  →  단계 1 의 S4  →  단계 2 의 S5  →  S6(보험)
```

S1·S2 만으로도 "왜 이 센서가 1등인가"는 해소된다. S4 는 "두 그래프를 눈으로 비교하는"
행위를 처음으로 성립하게 만드는 변화라 체감이 가장 크다.

**S5(랭킹 변경)는 보류를 권한다.** 근거가 웨이퍼 1장이고, 자동 지표로는 옳고 그름을
가릴 수 없다(6절). 단계 0·1 을 먼저 적용하면 사용자가 진폭·지속을 직접 보게 되므로,
그 상태에서 "그래도 순위가 이상하다"는 피드백이 나올 때 S5 를 실데이터로 검증해
도입하는 편이 안전하다.
