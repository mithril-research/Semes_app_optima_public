# 요구사항 명세서 — 챔버 이상 검사 시스템 (ChamberInspect)

| 항목 | 내용 |
|---|---|
| 문서 | 요구사항 명세서 |
| 대상 | 챔버 이상 검사 시스템 (ChamberInspect) |
| 적용 설비 | 웨이퍼 세정 설비 챔버 DSV1~6 |
| 운영 환경 | Windows 7 Professional K SP1 64bit (제어기, 폐쇄망) |
| 작성일 | 2026-08-25 |

---

## 1. 개요 (역할, 목적)

### 1-1. 요구 사항과 목적

**역할**

설비가 웨이퍼를 처리하며 남긴 센서 로그를 학습된 모델로 분석해, **불량이 의심되는
웨이퍼를 검사자가 알아볼 수 있게 제시하는 것**이 이 시스템의 역할이다.
판정을 대신 내리지 않는다. 근거를 보여 주고 판단은 사람이 한다.

**해결하려는 문제**

| 현재 | 문제 |
|---|---|
| 전수 육안 검사에 의존 | 장수가 많아 놓치는 웨이퍼가 생긴다 |
| 규격 초과만 확인 | 규격 안이지만 서서히 나빠지는 추세를 못 잡는다 |
| 이상 발견 후 원인 추적 | 어느 센서·어느 구간이 문제인지 사람이 일일이 대조해야 한다 |

**목적**

1. **선별** — 검사자가 먼저 봐야 할 웨이퍼를 점수 순으로 제시한다.
2. **조기 감지** — 임계를 넘기 전이라도 LOT 단위 산포가 벌어지면 드러낸다.
3. **근거 제시** — 어느 센서가, 공정의 어느 구간에서 벗어났는지 그림으로 보인다.
4. **추적** — 검사 이력을 남겨 기간·챔버·유형별 추이를 되짚을 수 있게 한다.

**요구 사항**

| 번호 | 요구 사항 | 근거 |
|---|---|---|
| R-01 | 설비 원본 `.log` 를 변환 없이 그대로 읽어 검사한다 | 별도 변환 단계는 운영 부담이자 실패 지점 |
| R-02 | 웨이퍼별 이상 점수와 등급(양품·주의·경고·심각)을 제시한다 | 검사 우선순위 결정 |
| R-03 | 판정 기준(임계·등급 배수)을 현장에서 조정할 수 있다 | 설비·유형마다 정상 범위가 다르다 |
| R-04 | 이상 웨이퍼의 원인 센서와 문제 구간을 제시한다 | 조치로 이어지려면 근거가 필요 |
| R-05 | LOT 단위로 품질 추세를 본다 | 개별 판정으로는 서서히 나빠지는 흐름을 못 본다 |
| R-06 | 검사 이력을 보관하고 기간·챔버·유형으로 조회한다 | 이력 추적·보고 |
| R-07 | 지정 폴더를 감시해 새 파일을 자동 검사한다 | 사람이 계속 붙어 있을 수 없다 |
| R-08 | 인터넷 없이 설치·구동된다 | 제어기는 폐쇄망 |
| R-09 | 계산으로 나온 숫자는 그 산출 방식을 화면에서 확인할 수 있다 | 근거 없는 숫자는 신뢰받지 못한다 |
| R-10 | 검사 결과를 리포트(HTML/이미지)로 내보낸다 | 보고·공유 |

### 1-2. 설계 범위

**이 시스템이 책임지는 범위**

```
    [설비]  ──원본 .log──►  ┌──────────────────────────────┐
                            │      ChamberInspect          │
                            │  ① 로그 읽기·태깅            │
                            │  ② 모델 추론 → 이상 점수     │
                            │  ③ 판정·등급·산포 추세       │
                            │  ④ 화면 표시·리포트          │
                            │  ⑤ 이력 보관                 │
                            └──────────────────────────────┘
                                        │
                                   [검사자 판단]
```

**블랙박스로 간주하는 시스템 (설계 대상 아님)**

| 대상 | 이 시스템이 가정하는 것 | 가정이 깨지면 |
|---|---|---|
| 설비 제어 소프트웨어 | 정해진 형식의 `.log` 를 지정 폴더에 남긴다 | 검사 불가 — 형식 확인 후 파서 조정 필요 |
| 로그 형식(열 위치) | 탭 구분, C2=챔버 · I2=LOT · J2=유형 · A·B열=날짜·시간 | 화면 설정으로 열 위치 변경 대응 |
| 학습 모델 | 별도 학습 앱이 만든 `.onnx` + 메타 + 임계를 그대로 사용 | 임계 없으면 판정 보류로 표시 |
| 웨이퍼 실제 양·불 | 시스템은 알지 못한다. 정상 대비 벗어난 정도만 계산 | — |
| 조치·설비 정지 | 사람이 판단하고 수행한다 | — |
| OS·런타임 | Windows 7 SP1, UCRT, VC++ 재배포, 브라우저가 설치돼 있다 | 설치 배치가 사전 점검·안내 |

**모델 학습은 이 문서의 범위 밖이다.** 학습은 별도 앱(Ubuntu)이 담당하고,
이 시스템은 그 산출물을 소비하는 쪽이다.

### 1-3. 모델에 대한 요구 (블랙박스 경계에서의 요구)

모델 내부는 설계하지 않지만, 이 시스템이 성립하려면 모델이 다음 성질을 만족해야
한다. 학습 앱과의 **계약 조건**이다.

| 번호 | 요구 | 근거 |
|---|---|---|
| RM-01 | **정상 데이터만으로 학습이 성립**해야 한다 (불량 표본을 요구하지 않을 것) | 불량은 극소수·양상 제각각이라 모을 수 없다 |
| RM-02 | 점수와 함께 **시점×센서 단위의 오차**를 산출해야 한다 | 원인 센서·문제 구간 제시(R-04)가 이것 없이는 불가 |
| RM-03 | **IO(밸브 개폐)를 입력으로 반영**해야 한다 | 밸브 조작에 따른 정상적 급변을 이상으로 오인하면 오탐이 판정을 덮는다 |
| RM-04 | **판정 구간이 명시**되어야 한다 (공정 첫 스텝은 이전 공정 잔류로 정상인데도 오차가 큼) | 첫/끝 스텝을 판정에서 제외할 근거 |
| RM-05 | **유형별 임계**를 산출물에 포함해야 한다 (`search_best.json`) | 유형마다 점수 크기가 달라 전역 임계 하나로는 판정 불가 |
| RM-06 | 점수 정규화 방식(원점수/스텝평균)을 **산출물에서 식별 가능**해야 한다 | 앱이 타임포인트 정규화를 이중 적용하지 않기 위한 조건 |
| RM-07 | 배점(가중) 점수를 쓸 경우 임계 재보정 절차가 있어야 한다 | 가중 점수는 원점수와 분포가 달라 모델 임계를 그대로 못 쓴다 |

## 2. 동작 (시나리오)

### 2-1. 선행 조건

시스템이 정상 동작하기 위해 **시작 시점에 만족해야 하는 조건**이다.

| 구분 | 조건 | 미충족 시 동작 |
|---|---|---|
| 환경 | Windows 7 SP1 64bit, UCRT(KB2999226) 설치 | 실행 불가 — 설치 안내 표시 |
| 환경 | VC++ 2015-2019 재배포 패키지 설치 | 실행 불가 |
| 환경 | 최신 브라우저(Firefox/Chrome) 설치 | 화면이 비어 보임 — 설치 안내 |
| 환경 | 앱 폴더에 쓰기 권한 | 이력·설정 저장 불가 — 사유 표시 |
| 모델 | 모델 폴더에 `.onnx` + `recon_meta.npz` 존재 | 검사 불가 — 모델 지정 요구 |
| 모델 | `search_best.json`(판정 임계) 존재 | 검사는 되나 **등급 판정 보류** |
| 데이터 | 검사 대상 폴더에 원본 `.log` 존재 | "검사할 파일이 없습니다" |
| 데이터 | 로그의 센서 열 이름이 모델의 학습 센서와 일치 | 검사 거부 — 재학습 필요 안내 |

### 2-2. 후행 조건

검사 동작을 **마쳤을 때 만족해야 하는 조건**이다.

| 번호 | 후행 조건 |
|---|---|
| P-01 | 검사한 모든 웨이퍼에 이상 점수가 부여되어 있다 |
| P-02 | 임계가 있는 경우 각 웨이퍼가 4등급 중 하나로 분류되어 있다 |
| P-03 | 검사 결과가 이력 파일에 append 되어 재시작 후에도 남는다 |
| P-04 | 보관 대상 웨이퍼의 상세 데이터가 저장되어 상세 화면을 열 수 있다 |
| P-05 | 파일별 메타(챔버·유형·LOT·종료시각)가 기록되어 필터·산포에 쓸 수 있다 |
| P-06 | 화면의 산점도·불량률 추이·요약이 검사분을 반영한다 |
| P-07 | 중단된 경우에도 **판정이 끝난 분량까지는** 위 조건을 만족한다 |
| P-08 | 실패한 파일이 있으면 그 사유와 개수가 집계되어 표시된다 |

### 2-3. 기본 동작 시나리오

**시나리오 A — 자동 감시 (상시 운영)**

```
 1. 앱 시작
 2. 모델 로드 (임계·메타 포함)
 3. 감시 대상 폴더 주기 확인
 4. 새 .log 발견
 5. 태깅       — 챔버(C2) · 유형(J2) · LOT(I2) · 종료시각(A·B열)
 6. 정렬       — 모델이 기대하는 센서/IO 열로 맞춤
 7. 추론       — 과거 센서 + IO → 미래 센서 예측, 실제와의 차이 계산
 8. 점수화     — 복원오차 누적 → 원점수 → ÷(유형 임계 × 배율) → 이상 점수
 9. 등급 판정  — 1 미만 양품 / 1~2 주의 / 2~3 경고 / 3 이상 심각
10. 이력 append + 상세 보관
11. 화면 갱신  — 산점도 · 불량률 추이 · 1시간 현황
12. 4번으로
```

**시나리오 B — 검사자 확인 (이상 발견 시)**

```
 1. 상황판에서 심각 등급 발생 확인
 2. 산점도에서 해당 점 클릭
 3. 이상 분석 화면
      · 복원오차 누적 곡선 — 어느 구간에서 벌어졌는지
      · 센서별 이상 점수   — 어느 센서가 원인인지
      · 센서 클릭 → 실제 vs 기대 파형 비교
 4. (필요시) RCA 생성 — 밸브·IO 원본을 재분석해 원인 후보 제시
 5. 판단 → 조치
 6. (필요시) 리포트 내보내기
```

**시나리오 C — 추세 점검 (주기 점검)**

```
 1. 조회기간 지정 (날짜만 지정하면 그날 전체)
 2. 챔버별 불량률 추이 확인 — 칸 색으로 기간별 불량률
 3. 산포 추세 켜기          — LOT 단위 초과 강도
 4. 특정 LOT 구간이 붉어지면 그 기간으로 좁혀 재조회
 5. 해당 웨이퍼 상세 확인
```

**시나리오 D — 기준 조정 (초기 셋업 / 재보정)**

```
 1. 설정 → 유형별 판정 임계
 2. [자동] — 정상 웨이퍼 분포로 등급 배수 산출
 3. 적용 → 산점도에서 결과 확인
 4. 특정 유형만 어긋나면 그 유형 배율만 조정
 5. 저장 (이력의 원점수는 보존 — 표시만 재계산)
```

## 3. 제약 사항

### 3-1. 환경 제약

| 번호 | 제약 | 배경 | 대응 |
|---|---|---|---|
| C-01 | Python 3.8 이 상한 | 3.9 부터 Windows 8.1 이상 요구 | 3.8 고정 빌드 |
| C-02 | onnxruntime 1.14.1 이 상한 | 1.15.1 부터 Windows 8 전용 API 사용 | 모델 IR 버전 하향 도구 제공 |
| C-03 | 인터넷 없음 | 폐쇄망 | 외부 자원 0건 — 글꼴까지 내장 |
| C-04 | 브라우저가 구버전에서 멈춤 | Win7 지원 종료 | 해당 버전에서 동작하는 기능만 사용 |
| C-05 | 설치 파일을 USB 로 반입 | 폐쇄망 | 사전 다운로드 배치 제공 |

### 3-2. 데이터 제약

| 번호 | 제약 | 영향 |
|---|---|---|
| C-06 | 로그의 열 위치는 설비 설정에 따라 다를 수 있다 | 유형·LOT 열 위치를 화면에서 변경 가능하게 함 |
| C-07 | 일부 행이 손상된 파일이 존재한다 | 손상 행은 제외하고 검사, 제외 수를 화면에 표시 |
| C-08 | 같은 웨이퍼가 재검사될 수 있다 | 집계 시 최근 결과 하나만 사용 |
| C-09 | 원본 로그가 네트워크 드라이브에 있을 수 있다 | 파일 접근이 병목 — 병렬 읽기, 진행률 표시 |
| C-10 | 과거 데이터는 폴더가 여러 개로 나뉘어 있다 | 경로를 개수 제한 없이 등록 가능하게 함 |

### 3-3. 판정 제약

| 번호 | 제약 | 의미 |
|---|---|---|
| C-11 | 이 시스템은 **양·불을 확정하지 않는다** | 정상 대비 벗어난 정도를 제시할 뿐, 판단은 사람이 한다 |
| C-12 | 임계는 학습 데이터에 의존한다 | 정상 데이터가 편중되면 임계도 편중된다 |
| C-13 | 임계가 없으면 등급을 낼 수 없다 | 점수만 표시하고 판정 보류로 남긴다 |
| C-14 | 센서 점수 0~1 과 1~2 는 척도가 다르다 | 1 초과는 절대값이 아니라 센서 간 상대 순위 |
| C-15 | LOT 이 1장이면 산포를 낼 수 없다 | 해당 LOT 은 산포 추세에서 제외 |

### 3-4. 운영 제약

| 번호 | 제약 | 대응 |
|---|---|---|
| C-16 | 검사 중 앱을 닫을 수 있다 | 완료분은 즉시 이력에 반영(스트리밍 저장) |
| C-17 | 제어기 자원을 설비 제어와 나눠 쓴다 | CPU 코어 예약 설정 제공 |
| C-18 | 이력이 무한히 쌓이면 디스크가 찬다 | 보관 기간 설정 + 자동 정리 |
| C-19 | 앱을 새 버전으로 교체한다 | 데이터 폴더를 앱 밖으로 뺄 수 있게 함(복사 불필요) |
| C-20 | 설정을 다른 PC 에서 옮겨올 수 있다 | 앱 내부 경로는 상대 저장, 없는 경로는 경고 후 기본값 |

## 4. 용어

| 용어 | 뜻 |
|---|---|
| 복원오차 | 모델이 예측한 센서값과 실제값의 차이 |
| 이상 점수 | 복원오차를 누적해 유형 임계로 나눈 값. **1 = 판정선** |
| 유형(레시피) | 공정 조건 묶음. 로그 J2 칸의 값 |
| LOT | 같은 묶음으로 처리된 웨이퍼 집합. 로그 I2 칸의 해시 |
