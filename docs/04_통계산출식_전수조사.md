## A. 웨이퍼 단위 점수

### A-1. 복원오차 수준 level (모든 점수의 뿌리)

**[표시 위치]** 직접 표시되지 않음 — 아래 모든 점수의 입력.

**[산출식]**
```
residual[t,j] = actual[t,j] − predict[t,j]        (실제 − 모델 예측)
level[t,j]    = |residual[t,j]| ÷ limit[t,j]      (잔차 허용한계로 정규화)
level[t∉판정구간, :] = 0                           (첫/끝 스텝 등 keep-mask 밖은 0)
```

**[상세]** `limit` 는 학습 때 정상(OK) 웨이퍼의 잔차로 만든 **센서별(옵션: 스텝별) 허용한계**
(`recon_meta.npz` 의 `resid_abs_limit`)다. 따라서 `level=1` 이 "그 센서가 평소 흔들리는
한계만큼 벗어남"을 뜻한다. 원래 변동이 큰 센서는 한계도 커서, 센서 간 감도 차이가
자동 보정된다. 판정 구간 제외는 이전 공정 잔류(carryover) 오탐 방지.

### A-2. 원점수 score_raw

**[표시 위치]** 이상 분석 상세(추적용) · `predictions.csv` · `history.jsonl`

**[산출식]**
```
score_raw = Σ_t Σ_j max(0, level[t,j])            (NaN/Inf 는 0 처리)

모델이 score-avg 계열로 학습된 경우(search_best.json 에서 감지):
score_raw = 위 값 ÷ 유효 스텝 수(step≠0)          ← 학습 임계와 단위를 맞춤
```

**[상세]** 시간×센서 전체의 초과분 합 = "웨이퍼 복원오차 누적"의 마지막 값과 동일.
score-avg 분기가 없으면 점수가 스텝 수에 비례해 전 웨이퍼가 NG 가 된다(실측했던 문제).
저장은 `floor(·,3)`.

### A-3. 결정임계 decision (판정선의 실체)

**[표시 위치]** 직접 표시되지 않음 — 정규화 분모. raw 값은 `threshold_raw` 로 기록.

**[산출식]**
```
decision = base(유형별 학습 임계) × mult(유형별 배율, 기본 1.0)

base 탐색 순서: search_best.json 의 threshold_by_recipe[유형] → 전역 임계
둘 다 없으면 decision 없음 → 판정 보류(값을 만들지 않음)
```

**[상세]** base 는 학습 앱이 정상 점수 분포로 정한 값(OK 의 μ+3σ 계열). mult 는
설정 탭에서 현장 조정. 유형 매칭은 짧은키↔풀네임 접두 매칭.

### A-4. 이상 점수 (화면의 대표 숫자)

**[표시 위치]** 산점도 Y축 · 이상 분석 "이상 점수 X.XX / 판정 기준 1.00" · 웨이퍼 목록 ·
일별 목록 · 리포트

**[산출식]**
```
이상 점수 = floor( score_raw ÷ decision , 2 )      → 1.00 = 판정선
판정      = NG  if score_raw ≥ decision  else OK
```

**[상세]** 임계=1 정규화로 유형이 섞여도 한 축에서 비교·평균 가능. 표시가 '버림'인
이유: 0.999… 가 1.00 으로 반올림되어 판정선에 걸린 것처럼 보이는 것을 막기 위함.

### A-5. 타임포인트 정규화 모드 (per_tp)

**[표시 위치]** 설정 [판정 표시] 선택 시 산점도·목록의 점수와 툴팁("점수/타임포인트")

**[산출식]**
```
s_tp   = score_raw ÷ n_tp        (n_tp = 그 웨이퍼의 점수 구간 길이)
표시값 = s_tp ÷ thr_tp           (thr_tp = per_tp 절대 임계, 설정/자동 산출)
n_tp 미상이면: 같은 유형 웨이퍼들의 n_tp 중앙값으로 추정(ntp_estimate)
```

**[상세]** 공정 길이 차이 보정. 단 모델 score_norm 이 time/final 이면 **자동 무시**
(이중 정규화 — A-2 에서 이미 나눴기 때문).

### A-6. 등급 (양품·주의·경고·심각)

**[표시 위치]** 산점도 점 색 · 요약 카드 · 목록 배지 · 챔버별 불량률의 분자

**[산출식]**
```
r = 이상 점수 (A-4)
r < 1        → 양품
1 ≤ r < warn → 주의        (warn 기본 2.0)
warn ≤ r < crit → 경고     (crit 기본 3.0)
r ≥ crit     → 심각
decision 없음 → 판정 보류 (어느 등급에도 편입하지 않음)
```

### A-7. 등급 배수 자동 산출 [자동] 버튼

**[표시 위치]** 설정 → 유형별 판정 임계 → [자동] 클릭 시 입력칸

**[산출식]**
```
r_i  = OK 판정 웨이퍼들의 이상 점수 (8장 미만이면 산출 거부)
σ̂   = MAD( ln r_i ) × 1.4826
warn = exp(σ̂)   (하한 1.05, 상한 20)
crit = exp(2σ̂)  (하한 1.1,  상한 40)
```

**[상세]** 임계가 OK 분포의 μ+3σ 로 잡히므로 exp(σ̂)·exp(2σ̂) 는 정확히 **4σ·5σ 지점**.
로그공간을 쓰는 이유는 복원오차가 덧셈이 아니라 곱셈적으로 퍼지기 때문. MAD 는
이상치에 강건한 σ 추정.

### A-8. per_tp 자동 임계 제안

**[표시 위치]** 설정 → per_tp 모드 전환 시 자동 채움 / [자동] 결과

**[산출식]**
```
x_i = OK 웨이퍼의 s_tp,  l = ln x   (8장 이상 필요)
방법① 분위수 매칭(기본): 현재 raw 임계가 만들던 불량 개수를 보존하는 분위수로 이전
방법② μ+3σ:  thr = exp( median(l) + 3·(MAD(l)×1.4826) )
```

### A-9. 이상 센서 수 n_flag_sensor

**[표시 위치]** 이상 분석 상세 · predictions.csv

**[산출식]** `n_flag = #{ j : max_t level[t,j] ≥ 1.0 }` — 상한을 한 번이라도 넘은 타깃 센서 수.

### A-10. 배점 점수 S(w) 와 임계 θ(w) (배점 모드)

**[표시 위치]** 설정 → 센서 배점 모드 · 배점 판정 배지 · predictions.csv 의 `score_w_raw`

**[산출식]**
```
w[t,j] = 1.1 (그 시점 밸브 조건 규칙 참) / 0.9 (거짓) / 1.0 (규칙 없음)
S(w)   = Σ_t Σ_j w[t,j] · max(0, level[t,j])

θ(w) 재보정 — 모델 임계는 원점수 분포용이라 그대로 쓸 수 없음:
  방법① 분위수 매칭(기본): α = P( S_raw ≥ θ_raw | OK )   ← 원래 오탐률
         θ(w) = OK 의 S(w) 분포에서 상위 α 분위수 (로그공간)
         → 분포 모양이 달라도 오탐률 α 가 보존되므로 정당. FPR=α 함께 표시
  방법② σ 미러링: θ(w) = mean(S(w)|OK) + 3·std(S(w)|OK)   (단순, 덜 엄밀)
유형별로 각각 산출. OK 표본은 지정 폴더 재추론(권장) 또는 누적 이력.
```

## B. 센서·구간 단위

### B-1. 센서별 이상 점수 (0~2 막대)

**[표시 위치]** 이상 분석·이력 검색의 "센서별 이상 점수" 막대와 숫자

**[산출식]**
```
accum_j = 그 센서의 복원오차 누적 최종값 (판정 구간만, ProcessStep 0 제외)
ok_hi_j = 그 센서 OK 누적 상한 곡선의 마지막 값 (없으면 있는 센서들의 중앙값 폴백)
r_j     = accum_j ÷ ok_hi_j

r_j ≤ 1 :  score = r_j                          (상한 대비 비율 — 절대적 의미)
r_j > 1 :  score = 1 + (r_j−1)/(r_max−1)        (초과 센서 간 상대 심각도)
           r_max = 그 웨이퍼에서 가장 심한 센서의 r → 그 센서가 2.0
           초과가 하나뿐이거나 r_max≈1 이면 그 센서만 2.0
표시: floor(·,2) · 1.0 위치에 노란 기준선
```

**[상세]** 0~1 과 1~2 는 **뜻이 다른 눈금**이다. 초과분을 상대화한 이유: 전부 1.0 언저리로
뭉쳐 "어느 센서가 더 문제인지" 안 보이던 것을 해결. 따라서 1.4 vs 0.7 을 "두 배 나쁨"
으로 읽으면 안 된다.

### B-2. 복원오차 누적 곡선

**[표시 위치]** 이상 분석·이력 검색 "웨이퍼 복원오차 누적" 그래프 (마지막 값 = score_raw 와 동일 계열)

**[산출식]** `cum[t] = Σ_{τ≤t} Σ_j max(0, level[τ,j])` (센서별 그래프는 해당 j 만).

### B-3. 정상 범위 띠 (OK band)

**[표시 위치]** 누적 그래프의 옅은 배경 띠

**[산출식]** 학습 OK 웨이퍼들의 누적 곡선을 공정 진행률 0~100%(100 구간 격자)로
정렬해 만든 하한~상한 포락선. 임계 이상인 OK(오염 표본)는 제외 옵션. 스텝 배점
모드에서는 가중 곡선용 띠를 별도 산출.

### B-4. 이상 구간 음영 (문제구간 하이라이트)

**[표시 위치]** 누적 그래프의 붉은 음영 · 센서 그래프의 참조 음영

**[산출식]**
```
slope[i] = max(0, cum[i] − cum[i−1])              (시점별 증가분 — 음수는 0)
민감도 s(슬라이더 0~1, 기본 0.8 설정 가능):
  s 가 높을수록 slope 상위의 좁은 구간만, 낮을수록 완만한 구간까지 음영
연속 시점을 구간으로 병합해 표시. 웨이퍼 음영과 센서 음영은 같은 규칙(불변식)
```

**[상세]** 누적값이 아니라 **기울기** 기준인 이유: 누적이 큰 곳은 "이미 지나온 뒤"이고,
지금 나빠지는 곳은 기울기가 큰 곳이기 때문.

## C. Overview 집계

### C-1. 챔버별 불량률 추이 — 칸 숫자·색

**[표시 위치]** Overview 격자 칸(툴팁 불량/전체·%) · 좌측 챔버 평균

**[주의]** 칸 색은 **불량률(빈도)**이지 **점수 크기(심각도)**가 아니다. 점수 3.2 짜리
웨이퍼가 있어도 그 구간 100장 중 2장이면 2% 라 칸은 옅다. 심각도는 산점도·등급으로 본다.

**[산출식]**
```
bad   = [보기] 선택에 따라: 심각만 | 경고+심각 | 주의+경고+심각
불량률 = bad ÷ total × 100                        (total=0 이면 빈칸 — 0% 아님)
칸 색  = 불량률 5단계 — 챔버 램프(C-1b)와 같은 기준선을 쓴다
         0% / ~2% / 2~5% / 5~10% / 10% 초과
         ★ 2026-09-01 변경. 예전 경계는 25/50/75% 라 불량률 20% 여도 가장 옅은
           색이었고, 램프는 5% 면 이미 빨강이라 같은 화면에서 정반대로 읽혔다.
챔버 평균 = Σbad ÷ Σtotal × 100 (기간 전체)
         평균 숫자 색만 t = clamp(불량률/8, 0, 1) 그라데이션(초록→주황→빨강)
```

**[불량 수를 세는 잣대 — 중요]** 칸 안의 `bad/total` 숫자와 칸 색은 위 **[보기]**
선택(심각만 · 경고+심각 · 주의+경고+심각)을 따른다. 그러나 **툴팁과 칸 클릭 상세의
처리매수·양품·불량·불량률은 [보기]와 무관하게 항상 '심각'만** 불량으로 센다.
숫자가 읽히는 잣대를 한 곳으로 고정하기 위함이다(주의·경고는 참고 줄로 따로 표기).

> 과거 결함: 클릭 상세만 [보기] 기준을 쓰고 있어, 같은 칸을 마우스로 볼 때와 클릭할 때
> 불량 수가 달랐다. 2026-09-01 수정.

### C-1b. 챔버 실시간 상태 램프

**[표시 위치]** Overview 좌측 상단 챔버 타일 색·라벨(정상/주의/이상)

**[산출식]** 최근 N시간(기본 24) 웨이퍼를 웨이퍼ID로 중복 제거한 뒤, **'심각' 등급 수**
(`ng`)와 표본 수로 판정한다. 비율 기준이며 한 장으로 빨강이 되지 않는다.

```
rate = 심각 ÷ total × 100
total ≥ 20 :  rate ≥ 5  → 이상(defect)
              rate ≥ 2  → 주의(warn3)
total < 20 :  심각 ≥ 2  → 이상(defect)          (표본 부족 → 건수로 보수적 판단)
그 외        심각 ≥ 1  → 주의(warn3)
불량 0 일 때  max_ratio ≥ 0.90 → warn2 · ≥ 0.80 → warn1 · 그 외 normal
```

`max_ratio` = 그 챔버 웨이퍼의 이상 점수 최댓값(임계=1 기준). 기준선 5%/2%/20매는
환경변수 `IO_CH_RATE_DEFECT` · `IO_CH_RATE_WARN` · `IO_CH_MIN_N` 로 조정한다.

**[근거]** 임계는 정상 분포의 μ+3σ 로 잡히므로 정상 공정에서도 0.3% 안팎은 임계를
넘을 수 있다. 표본 변동까지 감안하면 수 % 대가 "평소와 다르다"고 말할 수 있는 선이다.

### C-2. 최근 1시간 생산 현황

**[표시 위치]** Overview 우측 카드

**[산출식]** 공정 **종료 시각**(로그 마지막 행) 기준 최근 1시간 웨이퍼를 A-6 등급으로
집계. `양품률 = 양품÷전체×100`. 항등식 `양품+주의+경고+심각 = 전체` 유지, 판정
보류는 별도 표기.

### C-3. 산점도

**[표시 위치]** Overview·개별 검사 산점도

**[산출식]** X=검사 순서/시간, Y=이상 점수(A-4), 판정선 Y=1.0, 점 색=등급(A-6).
재검사 웨이퍼는 최근 결과.

**[추세 배지]** 산점도 위 '점수 추세 상승/하락/안정' 배지는 **그려진 점들의 이상 점수**에
최소제곱 직선을 맞춘 기울기 부호다(순번 i 를 X 로 사용).

```
a = (n·Σi·y − Σi·Σy) ÷ (n·Σi² − (Σi)²)      y = 이상 점수
|a| < 1e-6 → 안정 · a > 0 → 상승 · a < 0 → 하락
```

> ★ **C-1(챔버별 불량률 추이)의 칸 흐름과 다른 값이다.** 칸은 *임계를 넘은 장수의

### D-1. 묶음(그룹)


### D-2. 초과 강도 (화면 기준값)

**[표시 위치]** 산포 추세 칸 숫자·색·툴팁(넘은 비율/넘은 폭)

**[산출식]**
```
r_i     = LOT 내 각 웨이퍼의 이상 점수 (임계=1 정규화 — 유형 혼합 성립 근거)
ex_i    = max(0, r_i − 1)
초과 강도 = mean(ex_i) = 초과율 × 평균 초과량
  초과율      rate    = #{ex_i>0} ÷ n
  평균 초과량 mean_ex = mean(ex_i | ex_i>0)
(내부 옵션 excess2: mean(ex_i²) — 크게 넘은 웨이퍼 가중)
```

**[기준선]** `ex_i = max(0, r_i − base)` 의 `base` 는 **심각 배수**다(기본 3배,
밴드 설정에 연동). 임계(1.0)부터 세면 임계를 살짝 넘긴 웨이퍼까지 전부 잡혀 칸이
온통 빨개진다 — 산포 화면은 '심하게 벌어진 구간'을 찾는 화면이므로 주의·경고는 넣지
않는다. `over=thr` 로 부르면 예전처럼 임계 기준. 응답의 `excess_base` 로 확인 가능.

  같은 LOT (0.4·0.9·1.3·1.8·2.4·3.6):  임계 기준 0.85(빨강) → 심각 기준 0.10(노랑)

**[상세]** 상방 부분적률(upper partial moment) 계열. 넘은 장수·넘은 폭 어느 쪽이
늘어도 값이 오르므로 "점점 많아지고 커진다"를 한 값에 담는다. 0 = 아무도 안 넘음.

**[그룹 최소 장수]** 초과 강도는 그룹 **평균**이므로 1장으로도 성립한다(min_n 무시).
흩어짐(IQR)만 최소 2장을 요구한다. → 2장짜리 LOT 에서 '첫 장 포함'을 꺼도
남은 1장으로 정상 계산된다.

### D-3. 내부 계산(호환 유지 — 화면 기본 아님)

```
spread: u_i = (r_i − median_유형) ÷ σ̂_유형,  disp = IQR(u),  D = disp ÷ baseline
        baseline = 전체 그룹 disp 의 중앙값
margin: −median(ln r) ÷ σ̂(ln r)   (임계까지 몇 σ)      Cpu = margin ÷ 3
```

## H. 커버리지 선언

화면에 나타나는 수치 중 위 목록에 없는 것은 **집계가 아닌 단순 개수/문자열**
(파일 수, 폴더 수, 경로, 버전)이다.

**같은 숫자가 여러 곳에 구현돼 있다는 점에 주의한다.** `server.py`(원본 계산),
`index.html`(화면에서 다시 하는 집계), `export_html.py`(내보낸 HTML 안의 재계산)
