# 탭 A. 검사 현황 (inspect)

## A-1. 요구사항 명세서

### A-1.1 개요 (역할, 목적)
- **역할**: 모델/검사 폴더를 선택하고 웨이퍼 이상탐지를 실행하여 결과 표·요약·챔버 현황을 보여주고, 리포트(그림+CSV)를 생성한다.
- **목적**: 현장 작업자가 한 화면에서 "검사 실행 → 결과 확인 → 리포트 저장"을 끝낼 수 있게 한다.

#### 설계 범위 (블랙 박스)
- 이상탐지 모델 추론 내부(onnx), matplotlib 렌더 내부, 파일 시스템/폴더 선택 대화상자(OS)

### A-1.2 동작 시나리오
- **선행조건**: 서버 기동 완료(`/api/status` 200), 유효 모델 1개 로드, 검사할 CSV가 폴더에 존재.
- **후행조건**: `STATE["results"]` 갱신, 결과 표/요약/챔버 현황 렌더, (요청 시) `reports/<모델>/` 아래 그림·predictions.csv 생성.
- **기본 시나리오**:
  1. 모델 드롭다운에서 모델 선택(또는 폴더 선택 대화상자).
  2. 검사 폴더 지정 → "검사" 클릭 → 서버가 웨이퍼별 점수/판정 산출.
  3. 결과 표·불량 요약·챔버(dsv1~6) 현황 표시.
  4. "전체/선택/1장" 리포트 생성 → 진행률 칩 표시 → 완료 시 CSV 링크.

### A-1.3 제약사항
- 점수는 임계=1 기준 정규화(29a 레시피는 1.1). 모델 변경 시 결과/그림 캐시는 모델별로 분리 보관.
- 리포트 생성은 서버 백그라운드 스레드에서 수행(수십 장 렌더 소요). matplotlib은 스레드 안전하지 않으므로 렌더는 단일 락으로 직렬화.

## A-2. 본 설계

### A-2.1 요구사항 접수
- **현상 기록**:
  1. 모델을 변경하면 기존 리포트가 전부 삭제됨.
  2. 리포트 생성 버튼을 누르고 다른 탭으로 가면 생성이 중간에 멈춤.
  3. 결과 표에 RCA("주요원인") 열이 있어 혼란.
- **개선 요청사항**: 리포트를 모델별로 보관, 탭 이동에도 생성이 끝까지 진행, RCA 열 제거, 챔버 기반 현황 추가.

### A-2.2 요구사항 개발
- **변경 범위**: `server.py`(리포트 경로/락/모델 clear), `static/index.html`(표·챔버·리포트 폴링).
- **제약 정의**: pyplot 전역상태 → 렌더 직렬화 필요. 모델 식별자(`_model_id`)로 리포트 폴더 네임스페이스.

### A-2.3 변경점 설계
| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 리포트 저장 | `reports/<웨이퍼>/` 단일 | `reports/<모델>/<웨이퍼>/` (모델별) |
| 모델 변경 시 | 리포트 전체 삭제 | 삭제 안 함(모델별 보존), reload 시 해당 모델만 |
| 리포트 렌더 | 락 없음(동시 렌더 충돌) | `_PLOT_LOCK` 직렬화 |
| 진행 표시 | 탭 이동/새로고침 시 유실 | pollReport 재개(서버는 계속 진행) |
| 결과 표 RCA | 있음 | 제거 |

## A-3. 디테일 디자인

### A-3.1 설명
검사는 `/api/inspect`가 폴더의 CSV를 읽어 웨이퍼별 점수/판정을 만들고 `STATE`에 캐시. 리포트는 `/api/report`(전체/선택) 또는 `/api/report/wafer/{wid}`(1장)로 트리거, `_run_report`가 백그라운드에서 `_make_wafer_report`(3종 + 상위 N 센서)를 웨이퍼마다 생성. 챔버는 파일명 PMCUNIT7~12 → dsv1~6 로 매핑해 집계.

### A-3.2 설계도 — Sequence Diagram (리포트 생성)
```
UI(검사현황)         server                     report thread            _PLOT_LOCK
  |-- POST /api/report ------>|                                            |
  |                           |-- thread start -->|                        |
  |<-- {started,total} -------|                   |-- _make_wafer_report   |
  |-- GET /api/report (1s) -->|                   |     ensure_plot(x3) --> acquire/release
  |<-- {running,done/total} --|                   |     ensure_sensor(xN)-> acquire/release
  |   (탭 이동해도 서버 계속)  |                   |-- done += 1            |
  |-- GET /api/report ------->|<-- running=False --|                        |
  |<-- {finished, csv} -------|                                            |
  * 동시에 상세/이력 탭이 plot 요청해도 같은 _PLOT_LOCK 으로 직렬화 → 충돌 없음
```

### A-3.3 UI 화면 구성
```
[모델 ▼] [모델 폴더 선택]  [검사 폴더: ______ ] [폴더 선택] [검사]
[요약: 전체 N · 불량 M · 커버리지 xx%]
[챔버 현황: dsv1..dsv6  (5단계 색 · 불량/전체)]
[결과 표: 체크 | wafer | chamber | recipe | 점수 | 판정 | 이탈센서수 ]
[전체 리포트 생성] [선택 리포트 생성]   (진행칩: 리포트 생성 중 12/40 …)
```

# 탭 B. 추세 분석 (trend)

## B-1. 요구사항 명세서

### B-1.1 개요
- **역할**: 기간별 이상점수 추세와 산점도를 보여 준다(현재 모델 이력 기준, 임계=1 정규화).
- **목적**: 시간에 따른 불량 경향과 웨이퍼 분포를 파악.
- **설계 범위(블랙박스)**: 이력 저장 포맷(history.jsonl), 차트 라이브러리.

### B-1.2 동작 시나리오
- **선행조건**: history.jsonl에 현재 모델 이력 1건 이상.
- **후행조건**: 선택 기간의 추세선/산점도 렌더.
- **기본 시나리오**: 추세 탭 진입 → 기간(1/3/6/12시간 등) 선택 → 해당 구간 점수/threshold=1 기준 그래프 표시.

### B-1.3 제약사항
- 모델을 바꾸면 옛 모델의 raw 점수(예: 19673)가 섞여 스케일을 망친다 → **현재 모델 이력만** 필터. 레거시(태그 없음) 이력은 보존.

## B-2. 본 설계
### B-2.1 요구사항 접수
- **현상 기록**: 모델 혼재 시 추세/산점도 스케일 붕괴, 유령/중복 점, 기간 고정.
- **개선 요청사항**: 모델별 이력 분리, 중복 제거, 기간 선택 추가, 임계=1 정규화 일괄 적용.
### B-2.2 요구사항 개발
- **변경 범위**: `_history_for_current_model`, `_hist_ratio`, 산점도 dedup, 프론트 기간 셀렉터.
- **제약 정의**: threshold≤0 이거나 미기재 항목 제외. 웨이퍼별 최신 1건만.
### B-2.3 변경점 설계
| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 이력 범위 | 전체(모델 혼재) | 현재 모델만 |
| 점수 축 | raw 혼재 | score/threshold(=1 기준) |
| 산점도 중복 | 유령/중복 점 | wafer별 최신 1건 dedup |
| 기간 | 고정 | 선택형(시간 단위) |

## B-3. 디테일 디자인
### B-3.1 설명
`/api/trend`가 `_history_for_current_model()`을 읽어 `_hist_ratio()`(score/threshold)로 정규화, 기간 필터 후 시계열/산점 데이터 반환. 프론트가 차트로 렌더.
### B-3.2 UI 화면 구성
```
[기간 ▼ 1시간|3시간|6시간|12시간|24시간]
[추세선: x=시간, y=이상점수(임계=1 파선)]
[산점도: 웨이퍼별 점수 · 임계=1 기준선 · 불량 색 구분]
```

# 탭 C. 상세 진단 (detail)

## C-1. 요구사항 명세서
### C-1.1 개요
- **역할**: 특정 웨이퍼의 복원 오버레이/히트맵/누적점수 및 상위 이탈 센서별 그림을 보여 준다.
- **목적**: 불량 원인 센서/스텝을 시각적으로 진단.
- **설계 범위(블랙박스)**: 렌더 함수 내부, ONNX 추론.
### C-1.2 동작 시나리오
- **선행조건**: 해당 wafer가 `STATE["recs"]`에 존재(현재 검사분).
- **후행조건**: overlay/heatmap/waferaccum PNG + 상위 센서 갤러리 표시(캐시 재사용).
- **기본 시나리오**: 상세 탭 진입 → 웨이퍼 선택 → 3종 그림 + 센서 목록 → 센서 클릭 시 개별 2단 그림.
### C-1.3 제약사항
- 모델 변경 시 recs 비워짐 → 캐시 PNG만 표시, 신규 렌더는 재검사 후. 임계=1 정규화 적용. RCA 텍스트 제거.

## C-2. 본 설계
### C-2.1 요구사항 접수
- **현상 기록**: 상세에 RCA("주요원인") 표기가 있어 오해 소지, 센서 파일명이 랭크뿐이라 식별 곤란.
- **개선 요청사항**: RCA 제거, 센서 파일명에 실제 센서명 포함, 그림 임계=1 기준.
### C-2.2 요구사항 개발
- **변경 범위**: `ensure_plot`, `ensure_sensor_plot`(파일명 `<랭크>_<센서명>.png`), 상세 탭 렌더.
- **제약 정의**: 렌더는 `_PLOT_LOCK` 직렬화. 캐시는 모델별 폴더.
### C-2.3 변경점 설계
| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| RCA 표기 | 표시 | 제거 |
| 센서 파일명 | 랭크만 | `00_p_005_PV.png` (실제명) |
| 렌더 동시성 | 락 없음 | `_PLOT_LOCK` |
| 임계 기준 | raw | =1 정규화(29a=1.1) |

## C-3. 디테일 디자인
### C-3.1 설명
`/api/wafer/{wid}/plot/{kind}`가 `ensure_plot`으로 캐시/생성. `/api/wafer/{wid}/sensors`가 상위 N 센서 목록, `/api/wafer/{wid}/sensor/{rank}`가 개별 센서 2단 그림.
### C-3.2 UI 화면 구성
```
[웨이퍼 ▼]  [이 웨이퍼 리포트 생성]
[overlay] [heatmap] [waferaccum]   (임계=1 파선)
[상위 이탈 센서 갤러리: 00_<센서명> 01_<센서명> …]  → 클릭 시 2단(실제vs기대 / 누적)
```

# 탭 D. 이력 검색 (search)

## D-1. 요구사항 명세서
### D-1.1 개요
- **역할**: 월 달력으로 과거 검사 이력을 탐색하고, 날짜→웨이퍼→상세(아카이브 재렌더)로 조회.
- **목적**: 입력 CSV가 삭제돼도 최소데이터(npz)로 상세를 다시 그려 이력 추적.
- **설계 범위(블랙박스)**: 아카이브 저장 포맷(float16 npz), 렌더 함수.
### D-1.2 동작 시나리오
- **선행조건**: `archive/<날짜>/<wafer>.npz` 존재, 현재 모델 센서 수 일치.
- **후행조건**: 달력의 일자별 평균 이상점수 → 날짜 클릭 시 웨이퍼 리스트 → 웨이퍼 클릭 시 상세 그림(임시 렌더 후 스트리밍, 자동 정리).
- **기본 시나리오**: 이력 탭 진입 → 달력 로드 → 날짜 선택 → 웨이퍼 리스트 → 상세.
### D-1.3 제약사항
- 아카이브는 이미지가 아닌 최소데이터(≈150KB/wafer)로 저장, 조회 때만 렌더. 검사 당시와 **모델 센서 수가 다르면 렌더 불가**(그 모델 로드 필요). 보관기간 지난 날짜 폴더는 자동 정리.

## D-2. 본 설계
### D-2.1 요구사항 접수
- **현상 기록**: 웨이퍼가 삭제되면 상세를 다시 볼 수 없음. 이력 탐색 수단 부재.
- **개선 요청사항**: 이미지 대신 데이터로 보관, 월 달력 기반 검색, 상세 재렌더.
### D-2.2 요구사항 개발
- **변경 범위**: `_archive_wafer`/`_load_archive`, `render_archive_plot/sensor`, 달력 엔드포인트(`/api/calendar`, `/api/archive/...`).
- **제약 정의**: 렌더는 임시폴더 → 전송 후 `BackgroundTask`로 삭제. `_PLOT_LOCK` 직렬화.
### D-2.3 변경점 설계
| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 이력 상세 | 원본 CSV 필요 | npz 최소데이터로 재렌더 |
| 탐색 | 없음 | 월 달력(일 평균점수)→리스트→상세 |
| 저장 용량 | 이미지(큼) | ≈150KB/wafer |

## D-3. 디테일 디자인
### D-3.1 설명
`/api/calendar?month=` 이 월별 일자 평균점수 반환, `/api/archive/{date}` 웨이퍼 리스트, `/api/archive/{date}/{wid}/plot/{kind}` 가 `render_archive_plot`으로 그때그때 렌더해 스트리밍.
### D-3.2 Sequence Diagram
```
UI  --GET /api/calendar?month--> server: 일자별 평균점수
UI  --GET /api/archive/{date}--> server: 웨이퍼 리스트
UI  --GET .../{wid}/plot/{kind}-> server: _load_archive→render(_PLOT_LOCK)→temp png
                                   <-- FileResponse + BackgroundTask(rmtree temp)
```

|---|---|---|---|---|---|---|
| D-TC1 | 정상 | 달력 로드 | 아카이브 존재 | 이력 탭 진입 | archive/* | 일자별 평균점수 표시 |

# 탭 E. 설정 (settings)

## E-1. 요구사항 명세서
### E-1.1 개요
- **역할**: 레시피별 임계 배수, 이력 삭제, 아카이브 보관기간/삭제를 관리.
- **목적**: 현장에서 임계 민감도·보관정책을 코드 수정 없이 조정.
- **설계 범위(블랙박스)**: JSON 파일 저장/핫리로드, 파일시스템 삭제.
### E-1.2 동작 시나리오
- **선행조건**: 서버 기동, 쓰기 가능 data 폴더.
- **후행조건**: `recipe_multipliers.json` 갱신(핫리로드), 이력/아카이브 삭제 반영, 보관일 저장.
- **기본 시나리오**: 설정 탭 진입 → 레시피 배수 편집/저장 → (선택) 이력·아카이브 삭제(2중 확인) → 보관일 설정.
### E-1.3 제약사항
- 삭제는 되돌릴 수 없음 → **2중 확인** 필수. 레시피 배수는 즉시 반영(정규화·임계선). 보관일 0=무제한.

## E-2. 본 설계
### E-2.1 요구사항 접수
- **현상 기록**: 레시피별 임계 조정 불가, 이력/아카이브 무한 적재, 삭제 수단 없음.
- **개선 요청사항**: 배수 설정 탭, 자동정리(보관일), 이력·아카이브 삭제 버튼(2중 확인).
### E-2.2 요구사항 개발
- **변경 범위**: `_load_recipe_mult`/`recipe_multipliers.json`, `/api/history/clear`, `/api/archive/clear`, `/api/archive-retention`.
- **제약 정의**: 삭제 API는 2단 확인 프론트 가드. 보관일 변경 시 즉시 프루닝 대상.
### E-2.3 변경점 설계
| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 레시피 임계 | 코드 고정 | JSON 편집·핫리로드 |
| 이력/아카이브 | 무한 적재 | 보관일 자동정리 + 수동 삭제 |
| 삭제 안전장치 | 없음 | 2중 확인 |

## E-3. 디테일 디자인
### E-3.1 설명
`/api/recipe-mult`(GET/POST)로 배수 조회·저장(핫리로드). `/api/history/clear`, `/api/archive/clear`가 삭제, `/api/archive-retention`이 보관일 설정. 프론트는 삭제 시 confirm 2회.
### E-3.2 UI 화면 구성
```

[이력 관리]  보관일: [30]  [저장]   [이력 전체 삭제] (확인2회)
[아카이브]   [아카이브 전체 삭제] (확인2회)
```
